Status: CANONICAL
Version: 3.0

Effective: 2026-11-24
Method: methods/analyst_methodology.md
Previous schemas including v2.1 are SUPERSEDED for new reports only.

## Human-readable report (Turkish)
1. Fixture, competition, kickoff, AS_OF, method and status.
2. Independent DATA baseline: both teams, comparable samples, relevant statistics, source IDs and limitations.
3. Material findings: observations vs interpretations, source evidence, opposing evidence, hypothesis status; include autonomous research findings, not only data tables.
4. HUMAN: source discovery, permitted observations and exposure limitations, additional tested claims, discarded/unresolved claims, baseline changes. No raw predictions or news.
5. Conditional football scenarios and uncertainties, considering all seven outcomes without preference/score/probability.
6. Research audit and source ledger (structured JSON below), actual quality gate result; short 1–3 verified English display findings. No score field.

## Structured audit (JSON; actual values, not placeholders)
Required top-level fields:
- role: "ANALYST"; methodology_version: "analyst-v3.0-canonical"; protocol_revision: "3.0.5"; status: "READY" | "PARTIAL" | "BLOCKED".
- fixture_uid, match, competition, kickoff_utc, as_of_utc; home_team, away_team; competition_country, home_country, away_country (English country names), cross_border (boolean). Country metadata helps fixture identity and query spelling; it never selects or excludes HUMAN sources.
- startup_verified, isolation_verified (departmental evidence separation), no_prohibited_inputs (no prohibited information USED as evidence or decision input, not a claim of no accidental exposure), no_predictions: booleans; blocked_reasons: array of strings.
- sources: array of {id, url, observed_at, retrieved_at, provider, scope, claim}, with actual provenance; unique IDs. observed_at is the time information was available (<= AS_OF), not the retrieval time for a valid historical snapshot.
- baseline: {frozen_at, snapshot_id, home_evidence_ids:[], away_evidence_ids:[], summary, limitations:[]}; frozen_at <= HUMAN extraction start.
- human: {exposure_log:[], started_at, applicable_sources:[], attempts:[{source,query_or_url,status,reason,article_url?,author?,published_at?}], claims:[{id,source,claim,status,evidence_ids:[],countertest_id}], no_coverage_reason}. HUMAN records only source research by ANALYST. exposure_log records source/category and discard/mitigation only, never the prohibited content; empty if none observed. Include residual editorial anchoring risk in limitations; statuses FOUND / NOT_FOUND / INACCESSIBLE / EXCLUDED. Applicable names match the entire 14-source registry exactly for every fixture. Country metadata does not filter eligibility. Record actual fixture-targeted discovery per source in query_or_url (actual query including domain filter or exact fixture-targeted search URL; compact text, no duplicate log). batch requests may cover several sources, but no-source-specific search cannot be labeled NOT_FOUND. Open only relevant candidate articles. FOUND means usable permitted football claim material, not just a page; otherwise EXCLUDED with reason.
- inquiries: array of {id,trigger,question,hypothesis,alternative,actions:[],evidence_ids:[],result,uncertainty,countertest_id}; if empty, no_inquiry_reason with actual screening justification.
- countertests: array of {id,actions:[],support_ids:[],oppose_ids:[],result,limitations}; result and limitations are non-empty strings (use an explicit no-known-limitations statement if appropriate); actual search/comparison, not planned actions.
- findings: array of {id,fact,interpretation,evidence_ids:[],countertest_id,status}; status VERIFIED / PARTIAL / REFUTED / UNRESOLVED.
- quality: structured object defined below (three quality gates; actual records, not only assertions).
- baseline_changes: array of documented changes or explicit no-change reason; limitations: array of strings; stop_reason.
- scenarios: array of conditional, non-ranked football scenarios; outcome_coverage: ["1","X","2","OVER_2_5","UNDER_2_5","BTTS_YES","BTTS_NO"] (coverage only, never evaluation scores).
- software_detail_bullets_en: 1–3 factual English statements, no forecasts. 
- routing metadata (run_id/market/selection) may exist only in a separate delivery envelope after report freeze, never in this research audit.

Each source ID referenced must exist in sources; every material HUMAN claim, inquiry and finding needs a counter-test ID. VERIFIED claims need actual supporting evidence; unsupported claims remain PARTIAL/REFUTED/UNRESOLVED and cannot be presented as verified. Preserve actual opposing evidence. Missing metrics are explicit. READY must pass the structural gate `node tools/validate_analyst_v3.mjs audit.json` (or actual execution of the same validate function in an available JS runtime) and factual/semantic review; do not claim PASS without actual execution. Record gate result outside the audit in report. PARTIAL/BLOCKED retain actual completed research, missing prerequisites or unfinished material work and next actions; never save as complete. If no runtime is available, preserve the completed research as PARTIAL/validation pending; do not claim PASS or block starting DATA. Historical reports stay unchanged.

## Research-quality audit (required for new READY reports)

- quality.data_checks: array of {id, team: HOME|AWAY, area: SEASON_RESULTS|RECENT_FORM|VENUE|OPPONENT_CONTEXT|UNDERLYING|OTHER, metric, scope, scope_reason, material: boolean, critical: boolean, unit_type: MATCH_SERIES|AGGREGATE, units:[{id,status,evidence_ids:[]}], attempts:[{provider,query_or_url,unit_ids:[],status,reason}], gap_reason, alternative_reason}. Required areas for BOTH teams are material (OTHER optional); SEASON_RESULTS and RECENT_FORM require adequate real FOUND data and are critical. Unit IDs must identify eligible fixtures or genuine aggregate scope; MATCH_SERIES enumerates every eligible fixture, not only available ones. Statuses FOUND / NOT_SEARCHED / NOT_FOUND / INACCESSIBLE / UNAVAILABLE. Actual attempts use the same statuses except NOT_SEARCHED; an attempt may cover multiple units. A FOUND unit requires linked evidence and matching FOUND attempt. Missing material units require attempted retrieval and a documented alternative path (another provider or distinct appropriate direct retrieval), or concrete alternative_reason if no appropriate alternative exists. UNAVAILABLE requires linked evidence of nonpublication; gaps need explanation. Material NOT_SEARCHED and any missing critical unit block READY; use critical only for evidence genuinely essential to adequate baseline/conclusion, not every advanced metric. Do not mark advanced metric gaps critical solely because data are unavailable. Genuine noncritical gaps may remain with explicit reasons. Include current competition xG series when relevant and available in part, and its full expected fixture set for each team.
- quality.human_contributions: one record per registered HUMAN source {source,kind: NOVEL_LEAD|DUPLICATE_ONLY|NO_USABLE_CONTENT|EXCLUDED,assessment,inquiry_ids:[]}; novel lead must link to actual inquiry; no invention if none. Record actual examination and novelty relative to frozen baseline.
- quality.matchup_checks: exactly HOME_ATTACK_AWAY_DEFENSE and AWAY_ATTACK_HOME_DEFENSE records {direction,mechanism,comparability,actions:[],evidence_ids:[],inquiry_ids:[],countertest_id,status: VERIFIED|PARTIAL|UNRESOLVED,limitations}. Actions must describe actual evidence searches/comparisons (including similar opponents or why none are accessible). VERIFIED requires supporting evidence; PARTIAL/UNRESOLVED may document genuinely unavailable comparable evidence, not unattempted research.
- quality.leads: array of {id,trigger,question,material:boolean,critical:boolean,status: RESOLVED|EXHAUSTED|OPEN,inquiry_ids:[],reason,next_action}. Every material lead requires an actual linked inquiry, with its countertest. RESOLVED means investigated, not necessarily confirmed; EXHAUSTED requires concrete search/limit and remaining uncertainty; material OPEN or critical EXHAUSTED/OPEN blocks READY. Record new questions from results, not just initial ones. If no additional leads, closure must explain actual review, not manufacture them.
- quality.closure: {data_review,depth_review,remaining_work_review,why_stop,material_work_remaining:boolean,critical_gap_remaining:boolean,stop_type: EVIDENCE_SUFFICIENT|NONCRITICAL_LIMIT|SESSION_LIMIT|BATCH_LIMIT}. Reviews are specific substantive explanations grounded in the above records. READY requires both booleans false and EVIDENCE_SUFFICIENT or NONCRITICAL_LIMIT, never SESSION_LIMIT/BATCH_LIMIT. A PARTIAL report retains actual completed work and remaining actions. These are content-audit fields, not scores or new agents. Structural checks do not establish semantic sufficiency or factual truth.

## Website compatibility
Same verified run_id in separate routing envelope. Legacy A input MUST remain blank/null; it is retired, not zero, neutral or missing-data penalty for v3.0. The complete original report (including audit) is the evidence payload; no market-directed research or numeric support. If the current site cannot accept this contract, report the incompatibility, do not force a save. FINAL interprets evidence and not legacy score; no new FINAL scoring formula is authorized.

## Compact audit and evidence reuse (v3.0.5)
All v3.0.3 required fields, cross-references, data-unit coverage, all 14 HUMAN attempts, matchup checks, leads and closure requirements are retained. Record each source once per relevant distinct evidence item and refer to its ID across checks; one actual batch attempt may list multiple covered units. A shared countertest ID is allowed when the recorded actual actions and result substantively test every linked claim; preserve limitations and opposing evidence. Short action strings and ID references are acceptable when they identify the concrete executed operation and result in the same audit. Do not repeat identical full logs in the readable summary. Keep the complete structured audit and source ledger in the original Markdown; no omitted records or external-only audit. Populate the audit during research, validate the completed audit and rerun only when a correction changes it. No mandatory timing fields or runtime threshold added; optional measured timing notes belong outside JSON. Quality gates and factual review are unchanged.
