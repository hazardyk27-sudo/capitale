# CAPITALE ANALYST — Autonomous Evidence Research

Status: CANONICAL
Version: 3.0
Operational revision: 3.0.7 — single ANALYST, two source categories
Effective: 2026-11-24
Owner-approved: standard baseline + human insight + autonomous deep research + critical review + evidence-only report.
SUPERSEDES v2.1 and all earlier ANALYST methods for NEW runs. No historical revision.

## Non-negotiable principles
Research the whole fixture symmetrically; never start from a desired outcome. Only allowed football-performance evidence, not current news, squad availability, odds, market predictions, SXF/POLY or another department. No recommendation, ordinal score, win probability, predicted score or directional lean in any ANALYST output. FINAL alone decides. Actual data and reproducible source traces are mandatory; plausible language is not evidence.

## 0. Preflight
Read the single binding prompts/analyst_start.md once per session; consult this detailed methodology when needed, not as a repeated startup task. Verify neutral fixture, competition, season, kickoff and pre-match AS_OF. Begin DATA as soon as permitted data access exists. Do not require a second agent, separate session, browser login, validator runtime or server deployment before research. Historic replay requires pre-cutoff evidence snapshots, not today's data. Keep routing separate until freeze; if selection or prohibited content is accidentally seen, record exposure type, ignore it and discard/rework affected claims. Do not pretend to have context isolation. Only actual missing critical research data/identity prevents research; validator and site are checked at their respective later stages.

## Efficient execution — operational revision 3.0.7

The objective is efficient research without lower evidence quality. Do not use a time target or batch size to end important research. Follow the one-active-fixture queue in prompts/analyst_start.md.

1. Plan the relevant comparison windows, eligible fixture IDs and information needs once. Retrieve permitted structured tables/fixture lists and match-level metrics in batches where available. Batch independent searches or use supported parallel retrieval within the DATA stage; keep DATA freeze strictly before HUMAN discovery. After freeze, batch independent registered HUMAN searches, and batch independent follow-up questions/alternative data requests when feasible. Do not create extra agents, paid services, background jobs or new runtime requirements. Sequential fallback is valid when parallel retrieval is not supported.
2. Maintain a compact, fixture-scoped working evidence ledger while researching. Index already retrieved evidence by actual provider, canonical page/fixture identifier, metric definition, sample/window and cutoff. Use existing source IDs for further calculations, questions, matchup checks and countertests when the data answer them. Record each actual retrieval once; a single retrieval can cover many units or data areas, referenced in each required audit record. Reuse permitted extracts and local calculations instead of reopening pages or recopying tables. Never reuse after-cutoff or other-department evidence, and never treat unverified cache as current evidence. Reopen only for missing material detail, material conflict, stale/ambiguous scope, corrections, or genuinely necessary independent corroboration; record the reason. Preserve source lineage and the frozen baseline.
3. Prioritize the research queue by plausible material change to whole-match understanding, not a desired result or the ease of a search. Merge overlapping questions and resolve several leads in one well-designed comparison where appropriate. Before a new retrieval, check whether existing evidence answers it and whether the proposed search can materially resolve uncertainty. A nonmaterial lead can be closed with a specific reason or retained as nonmaterial; do not manufacture new work or endlessly refine an already tested point. Material anomalies, plausible counterexamples, comparable opponent context, both matchup directions and critical data gaps still require the existing substantive investigation. Do not downgrade materiality for speed.
4. A single executed countertest may support several claims, inquiries, findings or matchup checks if it actually tests each relevant hypothesis. Use its common ID, supporting/opposing evidence IDs and specific results; do not repeat an identical search or calculation for each finding. Where hypotheses need different comparisons or source independence, perform the additional test. Reused evidence is not a new independent source. Factual verification and meaningful counterevidence remain compulsory.
5. Populate the ledger-v1 compact audit incrementally as actual work completes (schemas/analyst_report.md). Maintain one catalog of DATA units and actual retrievals; group identical coverage and link unit/retrieval/source IDs. Record HUMAN discovery and contribution together. Write each autonomous question, factual result, interpretation and uncertainty once; reuse inquiry IDs for findings, matchup checks and lead review where content matches. Keep distinct facts, actual actions, counterevidence and unresolved issues explicit. Assemble one Turkish Markdown: concise football synthesis, material statistics once, full compact JSON ledger, genuine gate result. Do not regenerate full research narratives or write an expanded audit; the validator expands references in memory. Mechanical rendering from the ledger is permitted, not a new research or runtime prerequisite. No new mandatory timing or efficiency fields, no truncation, no fake actions. If useful, note actual stage elapsed times and distinct retrieval/reuse counts outside the structured audit, only when measured.
6. Perform the three substantive quality reviews using the existing ledger, resolve real gaps, then execute the structural validator on the completed audit once. Rerun after any correction that changes the audit or if validation fails; never run repeatedly on unchanged data. A PASS does not replace factual/semantic review. Preserve PARTIAL work and next action when actual limits interrupt material research; pause the queue and leave the remaining fixtures QUEUED. Research and delivery remain separate.

Closure is a single focused review of remaining material work and attainable additional information, not a requirement to reread every source or repeat completed tests. If the relevant evidence and all required gates are complete and no viable material question remains, close promptly. These execution rules optimize the v3.0.3 quality standard; DATA COMPLETENESS, RESEARCH DEPTH and RESEARCH CLOSURE, actual validator PASS, evidence isolation, both-team scope and all 14 registered HUMAN attempts remain unchanged. Revision 3.0.7 changes reporting representation only; the v3.0.5 research procedure and acceptance substance remain in force. A fixed question count, source count, duration target or token budget cannot authorize READY.

## 1. DATA — independent baseline
Use the 18-source DATA registry, prioritizing official records and appropriate metrics, not all sites mechanically. Establish both teams' comparable season baseline, recent form, opponent quality, home/away, goals and underlying attack/defense metrics; inspect possession/style and relevant game-state information when sourced. Season, recent five/three/one windows and strength/venue context are useful starting points, not fixed analytical weights or mandatory report pillars. Include actual sample sizes, match identifiers, provider, time windows, source and missing-data statuses. Do not omit inconvenient fixtures; explain exclusions and comparability (competition, red cards, coaching-era boundaries when historical and allowed). Distinguish results from performance; never infer tactics from formation or possession alone. Save immutable baseline evidence and initial interpretation with timestamp and snapshot/hash before any HUMAN material is available. No picks or rankings.

## 2. HUMAN — single-agent claim discovery, not an authority
Use policies/analyst_human_sources.md and prompts/analyst_human_extract.md. After DATA baseline freeze, the SAME ANALYST searches all 14 registered HUMAN sources for the exact fixture, irrespective of countries/competition. Country/language only guides query spelling. Batch domain-targeted discovery for all 14, inspect only relevant candidate articles and log actual coverage per source; no need to open unrelated sites/pages. A result-free broad query does not establish source-specific coverage. HUMAN is a source category only. Prefer clean statistical/tactical passages or filtered retrieval; if a mixed editorial page is opened, extract only separable permitted factual/tactical observations. Never use or reproduce forecasts, betting picks, odds, confidence, consensus, current news or squad information. If encountered, record exposure category/source without content, discard it and counter-test the remaining claim from independent permitted DATA. If a claim cannot be separated, exclude it. Record actual source attempts, author, date, URL, reasons and limitations. No usable articles after actual discovery is a disclosed limitation, not a blocker. Reading human-authored commentary carries residual anchoring risk; independent baseline, verification and counterevidence remain mandatory.

## 3. AUTONOMOUS — discover, ask, test, adapt
The baseline and sanitized HUMAN claims are leads, not conclusions. Identify meaningful discrepancies, unexpected patterns, uncertainties, matchup mechanisms and possible causal alternatives. Independently generate your own fixture-specific research questions; no prescribed list of questions, mechanical factor scores or arbitrary quota of searches. Prioritize questions that could materially change understanding of the match. For each question record the trigger evidence, hypothesis and competing explanation, concrete search/query or data comparison actually executed, new evidence, result and remaining uncertainty. Investigate new questions arising from results, iterating DATA → questions → evidence → updated understanding; HUMAN may be re-consulted only through the same claim-only filtering and exposure-log rules. If no meaningful new question exists, document the actual screening and evidence-based stopping reason; do not fabricate questions or research. If material questions cannot be resolved, preserve them as unresolved rather than guessing.

## 4. CRITICAL REVIEW — mandatory counter-test
Before closure, challenge every material claim/hypothesis including initial impressions and accepted HUMAN claims. Search for counterexamples and plausible alternatives using comparable samples; record actual actions and supporting/opposing evidence even when none is found. Distinguish VERIFIED, PARTIAL, REFUTED, UNRESOLVED. Observations and interpretations are separate. Reject unsupported factual claims, avoid causation from correlation, no hindsight, no duplicate underlying evidence, no source-count voting. Reconcile scope, provider/metric definition, date, sample size and venue/strength differences; if conflicts persist, show both. Record exactly what changed from baseline and why. No change based only on a human author's authority. Independent verification of a published tactical observation may be impossible; label uncertainty and do not turn it into a verified fact.

## Three mandatory research-quality gates (v3.0.7)

These are stages of the existing ANALYST's own research, not additional agents, scores, services, fixed question quotas or startup dependencies. Apply DATA COMPLETENESS before baseline freeze for core facts and revisit for new data needs; apply RESEARCH DEPTH throughout investigation; apply RESEARCH CLOSURE before READY. Preserve the original frozen baseline; additions belong to later research, not a rewritten baseline.

### A. DATA COMPLETENESS
Define justified comparison windows before evaluating them. For BOTH teams document season/competition results, recent form, relevant venue splits, opponent quality and underlying attack/defense performance. Each must appear in the audit's data_checks with actual scope and scope rationale. For a match-level series enumerate the complete set of eligible fixtures (stable source match ID or date/opponent/venue label) and record the coverage of each fixture. In particular, when xG or another underlying metric is available for part of a relevant competition/window, seek it for the remaining comparable matches in that window for BOTH clubs; a missing aggregate page is not proof of missing individual match data. Do not shrink the comparison window to the matches already found. Include analogous checks for other material data needs discovered later. A justified single aggregate unit is permitted for truly aggregate facts; it cannot hide gaps in a match-level series. Keep provider definitions consistent; separate incomparable metrics rather than average them.

Use per-unit statuses FOUND, NOT_SEARCHED, NOT_FOUND, INACCESSIBLE, UNAVAILABLE. FOUND requires evidence and actual retrieval/search record. NOT_SEARCHED means no search, never "unavailable". NOT_FOUND means actual search did not locate it; INACCESSIBLE means documented access restriction; UNAVAILABLE requires evidence that relevant data are not published, not just a failed query. For every missing material unit, attempt appropriate alternate permitted source or direct match-level retrieval when the aggregate is incomplete; record the actual paths and results, or specific reason no appropriate alternative exists. Do not mechanically visit all 18 sources, bypass access limits, require every advanced metric in every league, or invent data. Important data with NOT_SEARCHED, unpursued viable alternatives, or material unresolved critical gaps cannot pass READY. Genuine unavailable advanced metrics may be disclosed if sufficient evidence remains; core result/fixture evidence for both teams must be adequate. If not, PARTIAL. Materiality and scope choices must be justified by football relevance, not convenience.

### B. RESEARCH DEPTH
HUMAN should uncover useful football observations, explanations or novel research questions, not simply repeat scores or recent wins. For every registered editorial source, record what was actually examined, whether its useful content is novel, merely duplicates DATA, is absent, or excluded; link novel leads to inquiries and explain limited contribution honestly. No quota for novel claims. Independently verify every accepted material claim; distinguish observable pattern from its inferred cause. For each material anomaly, contradiction or potential matchup mechanism, create a research lead and pursue it through the inquiry/countertest loop. New material questions revealed by results must enter the lead log before closure. Use actual evidence, not generic scenario language or plausible unsupported tactics.

Research the interaction of the two teams explicitly in BOTH directions: home attack versus away defense and away attack versus home defense. For each identify relevant evidence-led strengths/weaknesses, compare comparable historical opponent profiles if available (justify similarity and differences in quality, venue, competition and sample), investigate mechanisms and counterexamples. Explore chance creation/concession, tempo, pressing/transition/set-piece or other relevant mechanisms as evidence warrants, not as a mandatory metric checklist. Record actual matchup research and evidence/countertest links for both directions; when no comparable examples are available, document the searches, limitation and what cannot be concluded. Do not force tactics from possession/formations or label untested causes VERIFIED. Never infer actual performance from a conditional scenario. Track meaningful unanswered questions and continue research where a viable next action could improve understanding.

### C. RESEARCH CLOSURE
Before report freeze review the full fixture scope, material data gaps, HUMAN contribution, meaningful anomaly/contradiction follow-ups, opponent context, two-sided matchup and counterevidence. Every identified material lead must be RESOLVED (tested, not necessarily confirmed) or EXHAUSTED (actual relevant attempts with concrete evidence/access limit and residual uncertainty). An OPEN material question or reachable material data gap means continue researching or PARTIAL; do not declare it exhausted merely because time/context is short, many matches are queued, a fixed number of questions was reached, or the first provider failed. Unresolved but genuinely exhausted questions may remain in READY when they are noncritical and sufficient reliable evidence remains; critical unresolved gaps block READY. Report why additional feasible research is unlikely to materially change understanding; if an actual session/tool limit prevents completion preserve PARTIAL and next steps, pause the queue and leave other fixtures QUEUED. A batch size or desired time is not an actual blocker. No minimum question count or report length substitutes for content. The audit must include a specific closure review, not just three PASS strings. Actual structural PASS plus factual/semantic review remains mandatory; the validator checks recorded structure and consistency, not real depth, search execution or truth.

## 5. STOP AND REPORT
Stop as READY only after all three quality gates and when further feasible permitted research is unlikely to materially improve understanding; an actual session/tool limit that prevents completion of material work requires PARTIAL and pauses the queue. A planned time target or batch size is never sufficient reason to stop. Never claim exhaustion unless justified. A usable READY report requires actual source-backed baseline for BOTH teams, completed logged HUMAN discovery, recorded autonomous inquiry (or justified no material follow-up), counter-tests on each material claim and explicit limitations. If a required stage is incomplete, mark PARTIAL/BLOCKED with reasons; do not publish as completed. Missing advanced metrics or genuine no HUMAN coverage may be a limitation of a READY report if all research stages were actually executed and enough reliable evidence remains. Weak or absent basic data are not READY.

Report full fixture (not pick): verified facts and underlying statistics, material research findings, contradictions, opposing evidence, plausible conditional match scenarios (not forecast), uncertainties and research/evidence audit. Consider mechanisms relevant to all seven outcomes 1/X/2, O/U2.5, BTTS Yes/No without selecting, ordering, assigning scores or probabilities. Present no analyst lean, recommendations, predicted score, A/100, confidence number or market grades. No fixed length or forced charts; use tables when they clarify actual evidence. Include at least one genuine English finding (up to three) for site display, not a forecast.

## Fail-closed quality gate
Before marking READY, complete DATA COMPLETENESS, RESEARCH DEPTH and RESEARCH CLOSURE and confirm all of the following with actual records: startup and departmental evidence separation verified; pre-match temporal integrity; baseline frozen before HUMAN; both teams covered; all registered HUMAN sources actually attempted and logged, permitted claims and any incidental exposure recorded; autonomous research log or substantiated no-question justification; all material hypotheses and material findings linked to actual counter-tests; claim/source trace and missing/conflict disclosures; whole-match coverage; no prohibited fields/content; no fake actions. Use schemas/analyst_report.md and run tools/validate_analyst_v3.mjs on the structured audit. A failed/unavailable validator, absent critical evidence, or unverified required research action forbids READY and completed site save; retain actual research as PARTIAL, correct recoverable errors or return to the missing research stage on the same fixture. If genuinely unresolvable, pause the queue; do not start another fixture without explicit owner permission to skip. Execute the validator using any authorized JS runtime (Node CLI or the exact function with the actual audit in a code tool); do not require a particular machine. No tool execution is required at startup. Structural validation cannot prove semantic accuracy, truthfulness, or actual browsing: those remain required independent review. Record the validator's actual result; never self-assert that a tool ran. Site/FINAL integration must refuse non-READY or old-version new reports; live automatic gate deployment is a separate engineering task, not implied by these repository rules.

Only after the report is frozen and gate passed may the same ANALYST switch to delivery mode or use a separate routing context to attach verified existing run IDs/market/selection metadata. No revision to research based on routing. Keep all historical versions. Evaluate the new method prospectively and through time-safe backtests, comparing baseline-only vs HUMAN-enhanced findings, coverage, counter-test quality, contamination and downstream results. No performance gain is claimed before validation.
