# NEWS v2.1 — Fixed-source scan and report
Status: CANONICAL
Only active new-run method. Historical v2.0/v2.0.1 reports immutable.

1. Establish fixture, clubs, competition, countries, kickoff and real pre-match AS_OF. Do not use selection, odds or other-role evidence.
2. Build the finite scan list from the existing named entries in policies/news_source_directory.md: all listed sources for both domestic countries plus listed international sources, deduplicating shared URLs. Search only those sources, for each team individually or both together when coverage is sufficient. Use team aliases and appropriate local language; group compatible searches. For an unlisted country use the listed international sources only; disclose the missing domestic coverage. Do not invent or discover extra outlets.
3. For every applicable listed entry, make a real source-specific search or visit and read relevant accessible news articles. If an outlet is unavailable or no relevant news is found, record that outcome and continue. Search engines are navigation only; use source-restricted results and never use unlisted content. Do not bypass access restrictions. Do not endlessly retry blocked pages. Read relevant updates within the same approved sources where useful; no mandatory follow-up or counter-search per story.
4. Collect relevant pre-match news: manager, fans/stadium, local team developments, players, match significance, club/off-field, squad and preparation. These are topics to look for, not required news counts or a separate 16-cell gate. Exclude routine PR, generic motivation, ordinary fan logistics and unrelated material. Merge repeated news from the same origin; preserve material disagreements. Report what the article actually says, with source URL and published date/time if available. Do not convert uncertain reports into confirmed facts; where pre-match timing cannot be established, mark uncertain and do not use as verified prematch fact. Possible match effects may be briefly explained if supported; no prediction or score.
5. Create the concise but complete Markdown report per schema: fixture, news with references, a compact per-outlet scan table, limitations and 1–3 English findings/coverage statement. A real attempt at each applicable listed outlet and a completed report are the completion criterion. No requirement to obtain a news item, confirm every detail, eliminate every uncertainty, or obtain a validator PASS. READY means the prescribed scan/report is complete, not that all information is available. PARTIAL/BLOCKED only when the scan/report truly cannot be finished; name what was not done. Continue with other fixtures where possible; never claim unperformed work. No JSON audit, quality gates, mandatory new questions, arbitrary quotas or expanded search.
6. Save the complete report in the existing authenticated NEWS browser editor after research is frozen and run routing verified. N stays null. Use real AS_OF, full Markdown, genuine source links and 1–3 English factual findings (or a truthful coverage statement). Verify actual report ID/version. If the website or export is unavailable, provide the original Markdown file when possible and report delivery separately; never invent a save. No other role edits.
