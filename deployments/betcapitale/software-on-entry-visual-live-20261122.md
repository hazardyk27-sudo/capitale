# CAPITALE — Software-on-arrival persistent sample records → Match List v2 V20 LIVE (22 November 2026)

## Exact user requirement
User requested: whenever an SXF fixture becomes a Software match, Software's missing signal/A/V/N/B/O values should be generated automatically and **retained**. Match List v2 must copy these **already stored Software display values** when the fixture matches. Only when a fixture is **not** in Software should Match List create its own illustrative fallback, so the two interfaces do not drift. Do not modify unrelated design, original SXF signals, backend or logos. User previously removed small `SAMPLE` badges; never reintroduce those badges.

## Operational boundaries and rollback
- Production data matched by unique fixture/date and market. If conflicting Software market/selection for same teams exists, Social intentionally does not arbitrarily choose one, instead displays its existing deterministically generated fallback. If Software data is missing entirely for a coupon fixture, no fake Software run is created; Social can still populate that coupon fixture. This ensures no false identity while preserving the user's real-first rule.
- Existing Software admin UI reads real `/api/admin/software` and computes equivalent seeded samples **immediately**. Materialized snapshot is updated from source once per minute by worker, not via a Supabase insert hook; user should be told this nuance explicitly. Therefore actual database 'on insert' instantaneous persistence was NOT implemented, and no private database record was changed.
- Public feed snapshot backup and original systemd unit at `/app/betcapitale/rollback-software-on-entry-materialized-20261122/`. To revert server job, remove only `/etc/systemd/system/capitale-public-software-feed.service.d/20-materialized-visual.conf`, `systemctl daemon-reload`, and optionally restore backed-up public `/software/matches.json` when paused; the 0600 ledger is safe to retain unused.
