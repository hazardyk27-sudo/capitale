# CAPITALE — Real Software values first, deterministic illustrative fallbacks (LIVE 2026-11-22)

## User's requested behavior
User explicitly requested: when real data is available, fill from Software; when no data exists, fill missing fields with random-like values, including an SXF signal selected from the **existing configured signal code family**. Keep Match List v2 and Software numerically aligned. Keep club logos automatically sourced from local SXF names. Samples must not be mistaken for verified betting analysis.

## Implementation scope and exact rules
- **Software V24 + Social Match List v2 V18 deployed live together**, with a single reproducible sample engine compiled from `client/src/lib/capitale-visual-fallback.ts` (also injected byte-identically into Software V24 JS). Both use the same deterministic fixture key `'capitale-sample-v1|date|normalized_home|normalized_away'` and FNV-style seeded selection, so the same date/team fixture yields stable values across page refreshes and both interfaces. This is pseudo-random illustrative data, **not source signals and not live betting probabilities**. Signals are selected from existing V16 template codes: `PRM-6`, `MOM-8`, `STR-6`, `SLD-8`, `CRL-6`, `CNI-6`, `PRM-8`.
- **Real fields take priority independently**. Actual Software `signalCode`, `analystScore`, `newsScore`, `volumeShare`, `drawShare`, and valid market/selection+timestamped odds movement remain unchanged for display. When an individual field is null/empty/invalid it receives the shared illustrative fallback for that field. For a missing Software row, Match List v2 uses samples on the real today_matches fixture; Software **does not manufacture a fake run/row** when its authoritative source has none.
- Default illustrative ranges (same as prior design mockups): A 61–92, V 67.0–97.5%, N 55–88, B 3.0–21.5%, O ±0.2–6.9%, sample signal from above list. Samples do not influence real filtering for actual stored Software runs, report editing, agent workflow, Supabase tables, result accounting, or backend source endpoint. Synthetic values are generated **only in frontend display**, without API POST or database writes.
- Social V18 layers `capitaleVisualOverlay()` over the unchanged `deriveMatchList2()` verified-join result while retaining `metricSummary` from the **original verified source**. Its story/post passes `demoMode` only if at least one row has a sample, showing an `ILLUSTRATIVE VALUES` footer; each affected card has a small `SAMPLE` marker and each generated metric/signal has an illustrative tooltip. Admin reports real source match count and sample-filled row count separately. Real SXF names, kickoff times, result status and local logo paths preserved.
- Software V24 is generated from immutable V23 by `/opt/capitale-shared-real-first-fallback-v24-20261122/build-software-v24.py` and common TypeScript transpiler `build-software-v24.mjs`. The actual existing Software rows render the same fallback values for A/V/N/B/O and missing signal. A small `SAMPLE` note appears on generated rows; source objects and reporting APIs are not mutated. Existing white cards, mobile spacing, sources, and 629 local crest integration remain.
- **Data reconciliation boundary:** `deriveMatchList2()` matches by date + normalized home/away and accepts unique Software market+selection only. If multiple conflicting Software market/selection rows are present for a fixture, the Social source join intentionally does not assert a real match; it may show a *clearly labelled illustrative* row rather than arbitrarily select one; Software continues to show its real separate rows. This is not a source reconciliation guarantee for ambiguous fixtures.
