# CAPITALE Software V23 + Match List v2 V17 — Real-data parity · LIVE 2026-11-22

## Owner request
User asked whether missing, nonautomatic values are random and whether the Software and Match List v2 numeric data are synchronized, explicitly saying **no mismatched data is acceptable**. Maintain verified signals and authentic SXF source; no invented percentages or match scores in real displays.

## Two real discrepancies confirmed before modification
1. The **Match List v2 V16** Social page opened by default with `matchV2Sample=true`, so it overlaid fabricated deterministic match/date-keyed *demo-only* SXF signals and A/V/N/B/O figures over the source-backed Software feed. Different from Software for the exact same fixture.
2. **Software V22** included `capitaleDisplayScore(id,role)`, a deterministic pseudo-score generator for missing Analyst/News support scores. The generated score could appear in Software sorting, desktop table, 3D match cards and expanded detail, while Match List's real-feed join deliberately kept A/N empty if the source lacked evidence. Software odds movement ignored timestamps, while Match List required timestamped reference/current odds and market+selection; their O figures could differ.

## Completed solution (single verified source, no invented values)
- Both screens already use **the exact same authenticated `/api/admin/software` endpoint** (the production backend uses the secured `capitale_admin_software_feed` RPC and maps actual SXF, Analyst and News reports). No database mutation or new endpoint needed.
- **Match List v2 V17** isolated worktree `/opt/capitale-software-en-60048de8ba8f9736466a0d5ca13594d6b9023d87/betcapitale-admin-matchlist-v2-verified-sync-v17-20261122-work`: deleted `sampleMatchList2Metric()` generator, removed default-on demo state, removed demo toggle from the actual Social Match List v2 interface, removed poster `demoMode` override, and made `matchListV2Metrics = verifiedMatchListV2Metrics` unconditional. The existing `deriveMatchList2()` protected join verifies fixture date, SXF-standardized both team names, one unambiguous market/selection, no inconsistent Software versions, and rejects `SYNTHETIC` rows. It leaves uncertain/missing data `—` and still resolves club PNGs without a Software signal. Software feed refresh set to every 90s while Match List is open with `cache:no-store`; both screens refetch on focus.
- Match List admin status now says `MATCH LIST V2 · VERIFIED SOFTWARE DATA`, shows actual verified/missing/ambiguous counts, no demo controls. A manual `Refresh Software values` control stays. Local 629-club logo lookup, original fixture/team/time, 3D white layout, story/post, results remain unchanged.
- **Software V23** derived from exact immutable V22 SHA `b0cccb6e7ac5f171f74b1eed66567d291ce6226ec77aec2c3cf0f5d0b82f3734` using a reproducible narrowly scoped builder `/opt/capitale-software-verified-sync-v23-20261122/build-v23.py`. `capitaleDisplayScore()` has been **removed** from its entire compiled module. Verified A/N scores display from the source, formatted as 82%/75% in Software 3D card to match Match List's style, numeric in the detailed table, and as `—` when absent. Percentage shares use exactly source-validated values within 0–100 and consistent rounding. Odds O requires nonempty market/selection, valid evidence timestamps in order, and both positive real odds >1 (same as Match List). Both screens read `/api/admin/software` every 90s while open, and Software request bypasses browser cache.
- No source, score, odds, signalCode, money-share values are generated or written to the real Software source. Existing Software CSS layout, icons, workflow, read-only report inspection, live endpoint, admin permissions, local crest integration and all other JS are unchanged.
